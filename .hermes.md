# Tape — Hermes Project Context

Hermes reads `.hermes.md` (this file) at session start. Claude Code reads the root
`CLAUDE.md`, which imports this file — so this is the one place project context is written.

## What this project is

Tape — free Android AR measurement app. Aim, tap, read the size. No subscription, no ads.

- Package: `com.tape.measure`
- Min SDK: 24, Kotlin 2.1.0, Jetpack Compose, ARCore, Hilt
- Status: pre-alpha. Line, path, area, angle, height, circle, box and cylinder tools are
  built and tested in the practice room. **Nothing has run on a physical phone yet** — the
  ARCore path is unverified until it does. Target device: Pixel 8a.

## Why it exists

iOS has had a built-in Measure app since 2018. Android doesn't. Paid AR measurement apps
charge ₹300–2,000/yr and lock basic features behind subscriptions. Free ones are stuffed
with ads and dark-pattern upsells. Tape is the fix.

## Design principles (non-negotiable, in priority order)

1. One job, done well: measuring real things with the phone. Distances and shapes now,
   body measurements later (see `.hermes/plans/local/`). Anything that isn't measuring is
   feature creep. (Scope widened from point-to-point only by Akshay, 2026-11-16.)
2. Free forever. No subscription, no premium tier, no upsells.
3. Honest about accuracy. Show confidence badges. Explain errors. Don't oversell precision.
4. Respect the user's time. Aim, tap, read. No tutorial walls.
5. Respect the user's data. No account. No analytics on what you measure. Local-first.

If any user request (including Akshay's) would cross these — push back, don't comply.

## Architecture and stack

- Kotlin 2.1.0 · Compose BOM 2024.12.01 · ARCore via SceneView · Hilt (DI) · KSP · Room ·
  kotlinx.serialization
- MVVM + UDF: Compose UI, ViewModels emit `StateFlow<UiState>`, screens observe
- All measuring logic is pure Kotlin under `domain/` and sees the world only through
  `domain/ar/ArFrame`. Two things implement it: `ar/ArCoreFrame` (a phone) and
  `sim/SimFrame` (the practice room). Keep ARCore types out of `domain/`.
- ARCore cannot run in the Android emulator on an Apple-silicon Mac (Google ships it for
  x86 emulators only). On the emulator the app falls through to the practice room: a
  simulated room of known sizes. That is how the tools are tried and tested without a phone.
- Local persistence in Room — no analytics, no remote sync

## Visual identity (golden rule)

**All token colors come from the runtime palette.** Every hex in the IDE theme
(`.vscode/themes/tape-warm-amber.json`) and in any HTML/design mockup should also appear
in `app/src/main/java/com/tape/measure/ui/theme/Color.kt`. When proposing visual changes,
always source from Color.kt — never invent a new palette.

Palette anchors:
- Accent (warm amber): `#E89B3C`
- Surface (warm near-black): `#0F0E0C`
- Foreground (warm bone): `#F4ECDF`
- Cursor / highlight (warm gold): `#FFC857`

## Build commands

```bash
./gradlew assembleDebug       # build APK
./gradlew installDebug        # build + install on the connected phone or running emulator
./gradlew testDebugUnitTest   # unit tests (includes measuring the practice room end to end)
./gradlew lint                # Android lint
```

Real AR needs an ARCore phone. The emulator runs the practice room only.

## Working agreements

- **Match repo conventions:** 4-space Kotlin indent; Compose `Modifier` first; small
  composables; prefer `derivedStateOf` over nested recomposition.
- **No paywall, ads, or analytics SDK.** Push back on requests that cross this line.
- **Min SDK 24 floor.** Don't pull in libs that require higher.
- **Sync Color.kt ↔ editor theme.** When Color.kt changes, `.vscode/themes/tape-warm-amber.json`
  must change in the same commit.
